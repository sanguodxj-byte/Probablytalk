# 上下文只进顾客可感知的

模型演的是柜台前的顾客，所以上下文的准入判据不是"游戏里有这个状态"，而是**他站在那儿能不能感知到**。

分界：

- **进**：他自己身上的（预算、现金、身份、性格、记忆、偏好、易感度、他这类人当场能看穿什么门道）；
  空间里看得见听得到的（其他顾客、招牌、垃圾堆、停电、当日新闻事件）；
  作用在他身上且他必然有感的（被当场改报价、被扫描、被敲诈或威胁、检查员到场、他刚拆穿过哪件货）。
- **不进**：只有玩家面板才呈现的数字与参数。他看不到店主兜里有多少钱、看不到加价率、
  看不到势力好感数值、看不到蓄水罐纯度、看不到议价倍率。

**Why:** 给他看后台数字会演出不合理的行为——一个顾客不该用店主的账本讨价还价；
更糟的是这些数字会压过他真正该反应的东西（标签、标价、气味、被当场识破）。
反过来，把玩家强改写成他感知得到的既成事实下发，他只能接着演：
组件与提示词都不给他任何否认、撤回或阻止的口子。

## 已核实（反编译 Assembly-CSharp，逐条查过读取方）

| 状态 | 读取方 | 结论 |
|---|---|---|
| `StoreStation.traffic` / `.happiness` | 全程序集只有构造器写入，**没有任何读取方** | 死值，删 |
| `StoreStation.order` | 只有 `Difficulty` 预设读 | 玩家侧，删 |
| `todayGutterflowPurity` / `todayRustwaterPurity` | `WaterHelper` 灌水时读 | 掺水是玩家后台动作，删；他只能通过手上那瓶水的标签与自己的验货能力察觉 |
| `retailMarkup` / `contrabandMarkup*` / `dealMakerBargainBonus` | 定价与加成 | 他看到的是**已经含加价的标价**，不是加价率，删 |
| `rentValue` / `loanValue` / `dayUntil*` / `storeReputations` | 店主的账本与好感 | 删 |
| `client.tradeReputationMultiplier` | 交易加成数值 | 删 |
| `PlayerStore.garbageLevel` | `HandleJanitorial`、`GetTrashAttPenalty`（**态度惩罚**） | 留：既看得见，游戏自己也用它罚顾客态度 |
| `PlayerStore.isPowerOn` | 供电与机器 | 留：灯灭与机器停是物理可见 |
| `StoreClient.realName` | — | 留（一度列为越权，判错）：那是他自己的真名，不是玩家私有情报 |
| `StoreClient.augTier` / `isAugScanned` | `AugScanner.CreateTooltip` 与扫描仪回调 | 留：是他自身的属性与被作用于的事件，不是店主的账 |

验货机制（另见 `ClientInsight`）：`StoreClient.OnItemPlaced → CanClientExposeAnyFeature → ClientExposeFeature`，
逐条 `CanClientExposeThisFeature` 通过就弹对质对话、非伪人势力好感 -4、`ExposeFeature(lowkey: true, playBad: true)`。
能力由 `CompleteClientCreation` 按 tag/势力赋值（SCAV/下层与黑市/游客/安保/上层/其余），
个别原型在工厂里覆盖；组件直接读委托方法名，不自己判、不抄表。

## 已撤回的两个说法

- 「顾客会喝水」：错。口渴在 `GameCharacterItem.maxThirst/currentThirst` 上，由
  `GameMaster.current.raidManager.GetAllPlayerCharacters()` 取，属玩家角色生存系统；
  `StoreClient` 没有任何 drink/thirst 成员。水对顾客只是交易物，验收看 `WaterFeatureHelper.GetCurrentWaterDisplay`。
- 「他打算验货」：错。游戏里没有意图阶段——放货那一刻判定即执行。

## 规矩归提示词，事实归上下文

同一个数字不许写两处。议价的幅度上下限、累计上限、可谈轮数只由提示词单方面下发
（`PromptBook.InteractiveFormat`），上下文里的 `minPercent/maxPercent/maxCumulative/roundsMax` 已删，
只留已经发生的事实：方向、已谈几轮、已让/已加多少、欠多少、这家店肯让他赊多少。
两处各写一份，改一处就自相矛盾，而模型会挑那份对它更有利的信。

## 机器检查

`python tools/check_context_limits.py` 第五条规则 `private-channel`：上下文通路文件里出现
`station.order|traffic|happiness|today*Purity`、`store.retailMarkup|contrabandMarkup*|dealMakerBargainBonus|
rentValue|loanValue|storeReputations|playerCash|appraiserLevel|vendingMislabel*|requestMislabel*|...`、
`client.tradeReputationMultiplier` 即报错。只认字段访问的形状，注释里提到这些词不报；
`garbageLevel` / `isPowerOn` / `storeName` 作为"看得见"的对照组写进干净夹具，防止尺子口径过宽。
